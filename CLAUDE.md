# Unboxed Board Game Rentals

Unboxed — a personal board game rental site for Metro Manila (own 8 games, rent them out; GCash payment, Lalamove delivery/returns). A Next.js (App Router) + Bootstrap/Sass site backed by MongoDB. See `README.md` for tech stack and current status.

## Commands

```sh
npm install                   # install dependencies
npm run dev                   # start the Next.js dev server (also syncs Bootstrap Icons fonts + deferred CSS first)
npm run build                 # production build (also syncs Bootstrap Icons fonts + deferred CSS first)
npm start                     # serve the production build
npm run assets:icons          # re-sync Bootstrap Icons fonts into public/fonts (after an icon version bump)
npm run assets:css:deferred   # recompile non-critical CSS into public/css/deferred.css
npm run seed                  # seed local MongoDB from src/data/games.json + bookings.json
```

There is no test suite or linter configured. `npm run dev` starts a local dev server (default `http://localhost:3000`).

## Architecture

- **Next.js App Router**, plain JavaScript (no TypeScript). Pages live under `src/app/`: `src/app/page.jsx` is the homepage (`/`), `src/app/games/page.jsx` + `src/app/games/GamesPageClient.jsx` is the game listing/booking page (`/games`). `src/app/layout.jsx` is the root layout (loads global Sass, Google Fonts links, `BootstrapClient`, and — when `NEXT_PUBLIC_GA_MEASUREMENT_ID` is set — `DeferredGoogleAnalytics`). `src/app/error.jsx` and `src/app/not-found.jsx` are the error/404 boundaries. There are no API routes (`src/app/api/` exists but is empty) — everything goes through Server Actions.
- **Shared UI lives in `src/components/`**: `Navbar`, `Footer`, `RentalPoliciesModal`, `ScrollToTopButton` are used on both pages; `games/GameCard`, `games/GameDetailsModal`, `games/AddressAutocomplete` are used on the game listing page. `components/analytics/` holds `DeferredGoogleAnalytics` plus `TrackedLink`/`TrackedElement` click-tracking wrappers (see Analytics below). `BootstrapClient` is a client-only component that dynamically imports `bootstrap/dist/js/bootstrap.bundle.min.js` inside a `useEffect` (Bootstrap's JS touches `window`/`document` at import time, so it must never load during server rendering) — once loaded it self-wires every `data-bs-toggle`/`data-bs-dismiss` element (navbar collapse, accordions, modals). The one exception is the game details modal on `/games`, which is opened programmatically (`Modal` instance via a ref) because its content depends on React state.
- **Game data and bookings go through Server Actions**, never API routes. `src/app/actions/games.js` (`'use server'`): `getGames()` returns all active games shaped for the UI (`imageUrl` → `imageSrc`, plus a derived `imageAlt`), used by both the homepage's featured games and the full listing page; `checkAvailability(startDate, endDate)` returns per-game availability by querying `Booking` for overlapping `confirmed`/`out-for-delivery`/`rented`/`return-pending` bookings (per the overlap rule in `project-overview.md` → Business Rules — `pending` bookings don't block). `src/app/actions/bookings.js` exports `createBooking(input)`, which re-validates everything server-side (dates, a `MAX_RENTAL_DAYS = 7` cap, PH mobile format, 6-digit GCash reference), rechecks per-game availability, computes pricing (rental subtotal, 10% multi-game discount, deposit total, grand total) from DB game prices — never trusting client-supplied amounts — generates a unique `BG-####` booking number, and creates the `Booking` with status `pending`. After the DB write it best-effort fires `sendBookingNotificationEmail` (`src/lib/notifications.js`, Resend) and `syncBookingToHubSpot` (`src/lib/hubspot.js`), each wrapped in its own try/catch so a failure there never fails the booking itself. `src/app/page.jsx` and `src/app/games/page.jsx` are async server components that call `getGames()`; `GamesPageClient` calls `checkAvailability()`/`createBooking()` client-side.
- **Sass entry point is `src/scss/main.scss`**, imported once from `src/app/layout.jsx`, for critical/above-the-fold CSS. It imports `_variables.scss` (Bootstrap variable overrides) *before* `@import "bootstrap/scss/bootstrap"`, so Bootstrap picks up the overrides — new variable overrides must go in `_variables.scss`, not after the Bootstrap import. Bootstrap Icons is imported last, with `$bootstrap-icons-font-dir` set to `"/fonts"` (absolute, since Next serves `public/` at the site root) so compiled CSS finds the font files at `public/fonts/`. `src/scss/deferred.scss` holds non-critical CSS (currently the carousel and offcanvas Bootstrap components) compiled separately by `npm run assets:css:deferred` into `public/css/deferred.css`, and loaded client-side, after paint, by `DeferredStylesheet.jsx` — see that file and `deferred.scss` for exactly which rules are safe to defer and why. Next's built-in Sass support is configured in `next.config.mjs` (`sassOptions.includePaths` points at `node_modules` so `@import "bootstrap/scss/..."` resolves).
- **`public/` holds static assets**: `public/img/` (site images, committed), `public/fonts/` (Bootstrap Icons font files, gitignored — regenerated by `npm run assets:icons`), and `public/css/deferred.css` (compiled from `deferred.scss`, gitignored — regenerated by `npm run assets:css:deferred`). Both regenerate automatically before `dev`/`build` via `predev`/`prebuild`. Never hand-edit either generated directory. `.next/` (Next's build output) is also gitignored.
- **Database**: MongoDB via Mongoose. `src/lib/mongodb.js` exports `connectDB()`, which caches the connection on `global._mongoose` (avoids reconnecting on every hot reload / serverless invocation) and reads `MONGODB_URI` (defaults to `mongodb://localhost:27017/unboxed`; override via a local `.env`, gitignored — see `.env.example`). Models live in `src/models/` (`Game.js`, `Booking.js`), matching the `Game`/`Booking` data model in `context/project-overview.md` (`#data-model`) — `Booking.games` is an array of `Game` ObjectId refs, `Booking.status` is constrained to the enum exported as `BOOKING_STATUSES`. `npm run seed` (`scripts/seed.mjs`) drops and repopulates the `games`/`bookings` collections from `src/data/games.json` and `src/data/bookings.json` (the seed fixture is maintained by hand). Booking status transitions after `pending` (`confirmed`, `out-for-delivery`, etc.) are still made directly in the database — no admin UI exists yet.
- **Delivery address**: `games/AddressAutocomplete.jsx` uses `@googlemaps/js-api-loader` (Places Autocomplete + a map pin) when `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY` is set, hard-blocking addresses outside a Metro Manila bounding box / NCR city allowlist; without the key it falls back to a plain text input with no validation.
- **Notifications and CRM sync**, both fired from `createBooking` after the booking is saved, both optional and independently gated: `src/lib/notifications.js` sends the admin booking-notification email via Resend (needs `RESEND_API_KEY`); `src/lib/hubspot.js` does a one-directional, frozen-at-creation sync of a Contact (deduped by phone) + Deal into HubSpot (needs `HUBSPOT_ACCESS_TOKEN`, `HUBSPOT_PIPELINE_ID`, `HUBSPOT_DEALSTAGE_ID`) — see `context/features/hubspot-booking-sync-spec.md`.
- **Analytics**: when `NEXT_PUBLIC_GA_MEASUREMENT_ID` is set, `DeferredGoogleAnalytics` (`src/components/analytics/`) renders `@next/third-parties`' `<GoogleAnalytics>` only after `window.load`, keeping gtag.js off the critical rendering path; `src/lib/analytics.js` exposes `trackEvent`, wrapped by the `TrackedLink`/`TrackedElement` components for custom event tracking on booking-flow interactions.
- **SEO**: metadata, JSON-LD structured data, and the sitemap/robots all resolve absolute URLs from `NEXT_PUBLIC_SITE_URL` (falls back to `http://localhost:3000`; set in `.env` once a production domain exists). `src/app/layout.jsx` sets `metadataBase` from it plus root `openGraph`/`twitter`/`alternates.canonical`/`robots` and a `title.template` (`%s — Unboxed`); `src/app/games/page.jsx` extends metadata with its own `openGraph`/`twitter`/`alternates.canonical`. `src/components/JsonLd.jsx` is a small server component that renders a `<script type="application/ld+json">` tag — the homepage emits a `LocalBusiness` node, `/games` emits an `ItemList`/`Product` node built from the same `getGames()` result already fetched on that page. `src/app/sitemap.js` and `src/app/robots.js` serve `/sitemap.xml` and `/robots.txt`; `src/app/llms.txt` serves an AEO/LLM-facing summary.
- **Deployment**: `amplify.yml` is the AWS Amplify build spec; `.github/workflows/deploy.yml` triggers an Amplify deploy on push to `main`. Don't assume auth, payment-gateway integration, or an admin dashboard exist — none are present in the repo (see `project-overview.md` → Phase 2 / MVP Constraints).
