# Unboxed Board Game Rentals

Unboxed — a personal board game rental site for Metro Manila (own 8 games, rent them out; GCash payment, Lalamove delivery/returns). A Next.js (App Router) + Bootstrap/Sass site, no backend yet. See `README.md` for tech stack and current status.

## Commands

```sh
npm install          # install dependencies
npm run dev           # start the Next.js dev server (also syncs Bootstrap Icons fonts first)
npm run build          # production build (also syncs Bootstrap Icons fonts first)
npm start              # serve the production build
npm run assets:icons  # re-sync Bootstrap Icons fonts into public/fonts (after an icon version bump)
npm run seed           # seed local MongoDB from src/data/games.json + bookings.json
```

There is no test suite or linter configured. `npm run dev` starts a local dev server (default `http://localhost:3000`).

## Architecture

- **Next.js App Router**, plain JavaScript (no TypeScript). Pages live under `src/app/`: `src/app/page.js` is the homepage (`/`), `src/app/games/page.js` + `src/app/games/GamesPageClient.jsx` is the game listing/booking page (`/games`). `src/app/layout.js` is the root layout (loads global Sass, Google Fonts links, and `BootstrapClient`).
- **Shared UI lives in `src/components/`**: `Navbar`, `Footer`, `RentalPoliciesModal` are used on both pages; `games/GameCard` and `games/GameDetailsModal` are used on the game listing page. `BootstrapClient` is a client-only component that dynamically imports `bootstrap/dist/js/bootstrap.bundle.min.js` inside a `useEffect` (Bootstrap's JS touches `window`/`document` at import time, so it must never load during server rendering) — once loaded it self-wires every `data-bs-toggle`/`data-bs-dismiss` element (navbar collapse, accordions, modals). The one exception is the game details modal on `/games`, which is opened programmatically (`Modal` instance via a ref) because its content depends on React state.
- **Game data is read from MongoDB via Server Actions** in `src/app/actions/games.js` (`'use server'`): `getGames()` returns all active games shaped for the UI (`imageUrl` → `imageSrc`, plus a derived `imageAlt`), used by both the homepage's featured games and the full listing page; `checkAvailability(startDate, endDate)` returns per-game availability by querying `Booking` for overlapping `confirmed`/`out-for-delivery`/`rented`/`return-pending` bookings (per the overlap rule in `project-overview.md` → Business Rules — `pending` bookings don't block). `src/app/page.jsx` and `src/app/games/page.jsx` are async server components that call `getGames()`; `GamesPageClient` calls `checkAvailability()` client-side when the user clicks **Check Availability**.
- **Sass entry point is `src/scss/main.scss`**, imported once from `src/app/layout.js`. It imports `_variables.scss` (Bootstrap variable overrides) *before* `@import "bootstrap/scss/bootstrap"`, so Bootstrap picks up the overrides — new variable overrides must go in `_variables.scss`, not after the Bootstrap import. Bootstrap Icons is imported last, with `$bootstrap-icons-font-dir` set to `"/fonts"` (absolute, since Next serves `public/` at the site root) so compiled CSS finds the font files at `public/fonts/`. Next's built-in Sass support is configured in `next.config.mjs` (`sassOptions.includePaths` points at `node_modules` so `@import "bootstrap/scss/..."` resolves).
- **`public/` holds static assets**: `public/img/` (site images, committed) and `public/fonts/` (Bootstrap Icons font files, gitignored — regenerated by `npm run assets:icons`, which runs automatically before `dev`/`build` via `predev`/`prebuild`). Never hand-edit `public/fonts/`. `.next/` (Next's build output) is also gitignored.
- **Database**: MongoDB via Mongoose. `src/lib/mongodb.js` exports `connectDB()`, which caches the connection on `global._mongoose` (avoids reconnecting on every hot reload / serverless invocation) and reads `MONGODB_URI` (defaults to `mongodb://localhost:27017/unboxed`; override via a local `.env`, gitignored — see `.env.example`). Models live in `src/models/` (`Game.js`, `Booking.js`), matching the `Game`/`Booking` data model in `context/project-overview.md` (`#data-model`) — `Booking.games` is an array of `Game` ObjectId refs, `Booking.status` is constrained to the enum exported as `BOOKING_STATUSES`. `npm run seed` (`scripts/seed.mjs`) drops and repopulates the `games`/`bookings` collections from `src/data/games.json` and `src/data/bookings.json` (the seed fixture is maintained by hand). Game reads go through the Server Actions in `src/app/actions/games.js`; there are still no API routes, and booking submission does not yet write to the database.
- **SEO**: metadata, JSON-LD structured data, and the sitemap/robots all resolve absolute URLs from `NEXT_PUBLIC_SITE_URL` (falls back to `http://localhost:3000`; set in `.env` once a production domain exists). `src/app/layout.jsx` sets `metadataBase` from it plus root `openGraph`/`twitter`/`alternates.canonical`/`robots` and a `title.template` (`%s — Unboxed`); `src/app/games/page.jsx` extends metadata with its own `openGraph`/`twitter`/`alternates.canonical`. `src/components/JsonLd.jsx` is a small server component that renders a `<script type="application/ld+json">` tag — the homepage emits a `LocalBusiness` node, `/games` emits an `ItemList`/`Product` node built from the same `getGames()` result already fetched on that page. `src/app/sitemap.js` and `src/app/robots.js` serve `/sitemap.xml` and `/robots.txt`.
- **Roadmap**: the plan calls for adding Web3Forms and deploying via AWS Amplify, plus API routes wiring the games/booking pages to MongoDB (currently only connectivity, models, and seed data exist). Don't assume booking API routes, auth, or payment integration exist unless actually present in the repo.
